Phone

Turn on Personal Hotspot. Plug phone into a charger so it doesn't sleep. Toggle "Maximize Compatibility" ON (forces 2.4 GHz — required for the ESP32).

Settings → Personal Hotspot
2

Hardware

Plug Pi power in. Plug C6 USB power in. Wait ~30 seconds for both to auto-join JoelAndroid. (Do NOT plug Pi into ethernet — that would override WiFi.)

~30 s boot time

Mac

Mac joins JoelAndroid automatically (it's in your preferred-networks list). Open RuView.xcodeproj, hit ⌘R. In RuView's Device Setup screen, type simha.local.

30-second smoke test (run on Mac before demoing)

# 1. Pi reachable via mDNS
ping -c 2 simha.local

# 2. SSH still works on the new network
ssh root@simha.local "systemctl is-active ruview-sensing mosquitto"

# 3. C6 radar is publishing and the Pi sees it
curl -s http://simha.local:3022/api/v1/nodes | python3 -m json.tool

Pass criteria: ping succeeds, both services active, Node 4 shows "radar_type": "MR60BHA2" and "status": "active".

If something is wrong

Mac can't ping simha.local

iPhone Personal Hotspot may be isolating clients. Two fallbacks:

  1. Mac Internet Sharing: tether iPhone to Mac over USB-C, then System Settings → General → Sharing → Internet Sharing → share to WiFi. Mac becomes the AP.
  2. Travel router (GL.iNet "Mango", ~$30) — bring this next time. iPhone tethers to router; everything else joins router's WiFi.
Pi joins JoelAndroid but C6 doesn't (or vice versa)

Verify on the Pi:

nmcli connection show --active
nmcli -t -f NAME,AUTOCONNECT,AUTOCONNECT-PRIORITY connection show | head

For the C6, check from a browser at http://ruview-c6-radar.local/ — ESPHome web UI shows current SSID + RSSI. If it's not connecting, the C6 may need a USB re-flash with the YAML at firmware/esphome/ruview-c6-radar.yaml.

iOS app says "Cannot reach server"

Make sure Simulator is on the same WiFi as the Pi. iOS Simulator inherits the Mac's network stack, so if the Mac can ping the Pi, the Simulator can too. Try typing the literal IP instead of simha.local:

# find Pi's hotspot IP from Mac
ping -c 1 simha.local | head -1
# 172.20.10.X is iPhone's usual subnet
Person count flickers or shows 0 when someone is there

MR60BHA2 needs a clear line-of-sight to the chest, range 0.5–3 m. The radar's cone is forward-facing (~120° × 3 m). Person must stand in front, not behind or to the side. Once stable, the bridge holds presence for 4 s through brief lock-loss (already configured).

I need a fallback if the demo really breaks

Plug ethernet back into the Pi at home, SSH in, re-test on home WiFi: ping simha.local && curl http://simha.local:3022/api/v1/nodes. If that works at home, the issue is workplace-specific (AP isolation, firewall). Reset by toggling hotspot off/on; or pull out the travel router.
